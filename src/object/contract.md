# Abstract Package Contract

The package MUST be self-describing, provenance-bearing, contract-bound, lifecycle-qualified, and structurally verifiable.

The package MUST NOT claim approval, installation, activation, deployment, production execution, behavioral correctness, or canonical status without explicit authority and evidence.

An empty `objects/` or `instantiations/` directory is valid when the Object has no embedded Objects or concrete instantiations; include a README or `.gitkeep` placeholder so the intended role remains visible in an archive.
