# Contributing

Work is organized through explicit release and feature branches.

- `main` is release-authoritative and receives changes only through a release event.
- Release branches such as `pre-alpha-1`, `pre-alpha-2`, and `release/1.0.0` preserve scoped release composition.
- Top-level feature branches use `feature/<short-name>` and merge into their target release branch.
- Commits should be coherent, meaningful, and written with a conventional prefix where practical.
- Do not claim validation, approval, or release completion without execution evidence.
